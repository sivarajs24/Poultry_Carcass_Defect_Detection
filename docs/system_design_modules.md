# System Design: Module Implementation

The **Poultry Carcass Defect Detection** system is composed of several interdependent modules that handle data preparation, model training, backend API services, inference execution, data persistence, and the user interface.

Below is a detailed breakdown of the implementation for each module:

## 1. Data Preparation Module (`prepare_yolov8_dataset.py`)
This module is responsible for unifying and standardizing raw annotations from multiple diverse datasets into a unified YOLO format suitable for model training.
- **Dataset Consolidation:** Reads from multiple source datasets (e.g., "Poultry Defects", "Chicken bruise") located in the `datasets/` directory.
- **Annotation Normalization:** Transforms varying annotation schemas (both bounding boxes and polygons) into the standardized YOLO format `[class_id x_center y_center width height]`.
- **Class Mapping:** Maps disparate dataset-specific classes into a consolidated list of 11 defect classes (e.g., `bile`, `bruise`, `dislocation`, `fracture`).
- **Output Generation:** Splits the data into `train`, `valid`, and `test` sets within the `datasets/merged_detection_yolov8/` folder and dynamically generates the `data.yaml` configuration file required for YOLOv8 training.

## 2. Model Training & Export Module (`YOLOv8_model.ipynb`, `export_models.py`)
This module covers the lifecycle of the machine learning model from training to deployment readiness.
- **Model Training:** The `YOLOv8_model.ipynb` notebook handles the training of an Ultralytics YOLOv8 model using the consolidated dataset generated by the Data Preparation module.
- **Model Export:** The `export_models.py` script converts the trained PyTorch weights (`yolov8n.pt`) into optimized formats like ONNX (`yolov8n.onnx`) for faster inference and broader compatibility in production environments.

## 3. Backend API Module (`web/backend/app.py`, `web/backend/config.py`)
Built using the **Flask** microframework, this module serves as the central communication hub between the frontend and the inference engine.
- **REST Endpoints:** Exposes API routes for processing different media types:
  - `/api/detect/image`: Synchronously processes uploaded images or base64 payloads.
  - `/api/detect/frame`: Handles real-time video frames from webcams.
  - `/api/detect/video`: Asynchronously processes uploaded video files.
- **Asynchronous Task Management:** For heavy video processing, it spawns background daemon threads (using Python's `threading` library) and provides a status polling endpoint (`/api/detect/video/status/<job_id>`) to track processing progress without blocking the main server thread.

## 4. Inference Engine Module (`web/backend/inference.py`)
This is the core computational module that interfaces with the trained YOLOv8 model to execute object detection and tracking.
- **Model Loading:** Dynamically resolves and loads the optimal available model (preferring `.pt` or `.onnx` formats defined in `MODEL_CANDIDATES`).
- **Image Processing (`predict_image`):** Runs the YOLO prediction pipeline on static images, returning annotated images alongside structured JSON metadata containing bounding boxes, class labels, and confidence scores.
- **Video Tracking (`process_video_file`):** Uses YOLO's built-in object tracker (`model.track(persist=True)`) to maintain object identities (Track IDs) across consecutive video frames, preventing duplicate logging of the same defect.
- **Data Encoding:** Handles conversion between binary/base64 network payloads and NumPy arrays compatible with OpenCV and Ultralytics.

## 5. Analytics & Persistence Module (`web/backend/db.py`)
This module provides a lightweight data layer to store telemetry and statistical data regarding the detected defects.
- **Database Engine:** Uses an embedded **SQLite** database (`analytics.db`).
- **Event Logging:** Records every unique detection (timestamp, class name, confidence, source) into a `detections` table. It smartly integrates with the video tracker to only log uniquely tracked defects rather than logging the same defect in every single frame.
- **Data Aggregation:** Exposes querying capabilities (`get_analytics`) to summarize detection counts grouped by defect class, enabling the frontend to render analytical dashboards.

## 6. Frontend Interface Module (`web/index.html`, `web/static/`)
The user-facing presentation layer that allows operators to interact with the detection system.
- **Static Assets:** Serves raw HTML, CSS (`web/static/css/`), and JavaScript (`web/static/js/`) to the browser.
- **Client-Side Integration:** Communicates asynchronously with the backend API to upload media, stream webcam feeds to the frame processing endpoint, and display the returned annotated images, bounding boxes, and analytic charts dynamically on the screen.
